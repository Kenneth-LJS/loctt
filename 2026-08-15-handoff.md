## 2. Automation infrastructure (the original ask)

The goal was an agent that implements UI features, tests them, reviews,
and repeats — unsupervised, without inventing requirements.

| Piece | Where | What it does |
|---|---|---|
| **Case index** | `tools/case-index/`, `docs/dev/case-index.json` | Parses all **937** acceptance criteria into a machine-readable index. Strict: an unparseable heading is an error, because a silently dropped case is one nothing will ever test |
| **Coverage gate** | `tools/coverage/` | Cross-references `// @verifies LST-3` tags against the index. A fabricated ID fails the build |
| **Playwright** | `tests/ui/` | Real seeded tracker + real `loctt ui` server per test. Nothing mocked — the flow docs assert behaviour reaching files on disk |
| **The loop** | `docs/dev/build-loop.md` | Per-ticket gates, each a command that exits non-zero. The agent never decides it is done |

Commands: `npm run cases:index`, `cases:check`, `cases:coverage --
--require LST-3,LST-4`, `test:ui`.

**Step 1's gate is deliberately inverted** — requiring a ticket's case
IDs *before* anything is tagged proves they exist. A hallucinated
`LST-99` fails in thirty seconds rather than at the end.

Currently **13 of 937 cases tagged**. That is the honest number: the UI
is mostly unbuilt, and the tags are the proof of what is not.

## 4. Git-sync merge semantics — decided, mostly unbuilt

Recorded in `docs/dev/decisions.md` §6 as **M1–M4**. The conversation
that produced them is worth knowing about, because two of my proposals
were wrong and yours replaced them.

| # | Decision | State |
|---|---|---|
| **M1** | Counters are not merged arithmetically. Renumber only colliding tasks by `created_at`; derive the counter from the result | `rekeyCollisions` fixed; **not wired** |
| **M2** | A contested field takes the later `updated_at`. No conflict schema | **Not built** |
| **M3** | Every history entry records enough to reconstruct what it changed | ✅ **Built** |
| **M4** | Body is last-write-wins, losing version written alongside | **Not built** |

**Why M1 changed:** I proposed sum-of-deltas. You pointed out that
renumbering the colliding tasks and deriving the counter from what
exists cannot drift from disk, and needs no base commit. Yours is
better.

**Why M2 changed:** I proposed a `conflicts:` block in frontmatter. You
argued history makes last-write-wins recoverable. That was right *once
M3 exists* — which is why M3 was built first.

**Still undecided** — four file types nobody has ruled on, all needed
before merging can work. My proposed defaults, which you called "sounds
good" but which are not recorded as decisions:

- `_history.yaml` — union by `(timestamp, kind, actor, field)`. Load-
  bearing: M2's guarantee fails if history itself does not merge
- `_comments.yaml` — union by comment id; deletion beats a concurrent
  edit
- `projects.yaml` / `queries.yaml` — union by entry id

## 5. `set-prefix` — core built, surfaces pending

**Why it exists.** Two independently-`init`ed trackers merging both mint
`T-`, but prefixes must be unique (enforced at `createProject`). The
remedy is renaming one — so the command has to exist before the merge
work can point at it.

**The immutability claim was wrong.** `editProject` refused prefix
changes citing immutability; `move.ts` already rekeys tasks safely. It
was never built, not unsafe. Docstrings corrected.

**Built** (`a466c5c`): `setProjectPrefix` rewrites projects.yaml, the
state counter, every task key, and the index as one operation. Numbers
preserved (`T-3` → `WEB-3`), old keys in `key_history`. A crash sentinel
at `local/prefix-rename.yaml` makes it recoverable;
`completeInterruptedPrefixRename` finishes it, idempotently.

### Remaining, in order

1. **Wire recovery** — `completeInterruptedPrefixRename` is never
   called. A crash today writes a sentinel nothing reads. `doctor`
   should report a pending rename. **Do this first**; the rest is
   additive, this is a hole.
2. **CLI** — `loctt project set-prefix <ref> <prefix> [--yes]`, with
   confirmation stating how many tasks will be renamed
3. **MCP** — `set_project_prefix` tool
4. **Web** — route + settings panel (PRU-44–46, M4)
5. **Integration tests** — CLI and MCP against a real tracker

Acceptance criteria are already written: `PRU-C10`–`C12` in
`docs/dev/surface-test-cases/flow-projects-users.md`, `PRU-44`–`46` in
the UI tree.

## 6. Then: field-level merging

Sync aborts when any file changed on both sides. Two clones that each
create a task both bump `state.yaml`, so it stops there — **reproduced**,
and pinned by an integration test in `tests/integration/git/with-remote.test.ts`
so nothing can silently restore a destructive mirror.

That abort is why `rekeyCollisions` has no caller: no merged task set
exists for it to scan. **Wiring it up alone would not help.**

Shape, once the §4 gaps are decided:

```
1. MERGE      per-file, per M1–M4 + the four undecided rules
2. NORMALISE  rekeyCollisions; rebuild the key index
3. VERIFY     no duplicate keys, no dangling project refs — else abort
```

All three in a staging directory, moved into `.loctt/` only once phase 3
passes. Sync is the path that produced four reproduced data-loss bugs;
phase 2 makes it write task frontmatter, which raises the blast radius.

For two-init trackers the merge assigns a **provisional prefix** so
uniqueness holds at every moment, then tells the user to run
`set-prefix`. The tracker must never be left in a state the codebase
believes impossible.

## 8. If you pick this up next

1. **Read `docs/dev/build-loop.md` first** if you are touching UI
   tickets. The gates are commands, not judgement.
2. **Never run two test suites concurrently** — each `pretest` rebuilds
   `dist/`, which the others spawn. ~30 scattered failures that do not
   reproduce in isolation.
3. **Every new test must be shown to fail.** Break the behaviour, watch
   it go red, restore. This session found four tests asserting the
   behaviour being reversed; the repo has shipped fourteen more.
4. **`known-gaps.md` is real.** Check it before reporting a defect as
   new.

   first real test of the loop end to end.
