# Architecture

LocTT is a local task tracker that stores tasks as markdown files in a `.loctt/` directory. It provides a CLI, an MCP server for AI agents, and a web UI — all backed by a shared core library.

## Monorepo Layout

```
packages/
  core/         Shared LocTT logic (task CRUD, query engine, config loading, git sync)
  contracts/    Shared TypeScript types and API shapes

apps/
  cli/          Command-line interface
  mcp/          MCP server for AI agent integration
  web/          HTTP server + API + web UI (same origin, no CORS)
```

All three apps operate directly on `packages/core`. The web app serves both API endpoints and the UI from one process — there is no separate service.

## Data Directory

LocTT stores everything under `.loctt/` in the project root:

```
.loctt/
  tasks/
    <ulid>/
      task.md          Frontmatter (YAML) + markdown body
      <attachments>    Any files placed alongside task.md
  config/
    workflow.yaml      Statuses, priorities, task types, relationships, custom fields
    queries.yaml       Saved query definitions
  state.yaml           Key allocation state (next key number)
  local/               Machine-local state (not published via git sync)
    sync.yaml          Git sync metadata
    reconcile.yaml     In-progress reconciliation state (temporary)
  docs/                Optional helper docs (generated by `loctt init`)
```

## Task Identity

Each task has two identifiers:

- **`id`** — a ULID, used internally for deconfliction and storage (folder name)
- **`key`** — user-facing reference like `T-123`, used in CLI commands and queries

Keys are allocated sequentially from `state.yaml`. If keys collide during git sync, the task with the earlier `created_at` keeps its key; the other gets rekeyed. Old keys are preserved in `key_history` and remain searchable.

## Data Model

The core entity is a **task**. Tasks can nest indefinitely via `parent`/`child` relationships. There are no separate "epic" or "ticket" types — use `task_type` to distinguish if needed.

Task data is a `task.md` file with YAML frontmatter for structured metadata and a free-form markdown body. Attachments are regular files in the task folder, discovered automatically.

Workflow values (`status`, `priority`, `task_type`) use config keys (e.g., `in_progress`) rather than display labels (e.g., "In progress"). Configuration lives in `.loctt/config/workflow.yaml`.

## Interfaces

- **CLI** — direct terminal access to all task operations. See [cli-reference.md](cli-reference.md).
- **MCP** — structured tools for AI agents. Enforces that metadata changes go through validated operations, not raw file edits. See [mcp-reference.md](mcp-reference.md).
- **Web** — HTTP API + browser UI, served from a single process bound to localhost. The API mirrors core operations; the UI talks to its own co-located endpoints.

## Git Integration

Git-backed mode is optional. When enabled, LocTT uses a dedicated `.loctt` branch with a sparse worktree to publish and sync task data across machines. See [git-sync.md](git-sync.md).

LocTT works fine without Git — it's purely local by default.
